# Findings
- AJDM currently has Linux-only private UDS permissions; Endpoint rejects Windows ACL stores. Engine/store have partial Windows path support. UI currently requires a separately started core.
- Existing CI only compiles Windows backend and tests model/net; no installer. jpackage requires target-platform build; GitHub Windows runner can supply that.
- No AJDM/ADM repo exists in the configured account; no signing secrets listed in existing private ArDownload repo. No signing certificate has been supplied.
- User chose publicly trusted signing. Identity verification and an enrolled signing account are required; do not substitute self-signing.
- Chosen transport: Windows-only authenticated IPv4 loopback, random 256-bit capability in an ACL-private descriptor, exclusive endpoint lock; existing POSIX UDS unchanged. Added common private-file helper for cookie copies and packaged profile.
- Packaged desktop starts matching bundled core and shuts it down through authenticated IPC so Windows TerminateProcess is not relied on for checkpointing.
- SSL.com IV supports individuals and eSigner automation. Published price $129/year plus cloud signing subscription (pricing page displays Tier 1 $15/month; billing selection affects final quote). Enrollment/identity and payment remain user-owned blockers to trusted signing. No purchase made.

- First Windows run passed model/net and four of five IPC scenarios, including byte-identical resume. Descriptor cleanup failed because Windows returns a null fileKey. Use private capability identity for Windows descriptor cleanup; retain fileKey for POSIX socket. Also require ACL owner identity and initialize owner only on newly created files.
- Packaging review: jpackage default application arguments are replaced when command-line arguments are supplied. Pass --core explicitly alongside --profile when spawning the native child, preventing accidental recursive desktop startup. Reference: Oracle jpackage Support Application Requirements.
- Windows run 38385483928 passes all model/net/IPC checks and starts all three bundled media tools. Runtime linking fails because --bind-services pulls jdk.jlink into a Temurin build without packaged jmods. Switch to an explicit runtime module set including crypto, locales, charsets, HTTP fixture support and OS metrics; exclude build-time service binding.
- First full Linux CI run failed: ffmpeg absent on fresh hosted runner, and adaptive timing tests contended with parallel CLI integration tests. Install the declared media test dependency and serialize project tests on hosted CI; keep correctness assertions unchanged.
- Run 38385901266 built app image and installer; core/CLI ping succeeded. Window check targeted jpackage parent process, but Windows native launcher restarts a child for DLL environment setup (OpenJDK WinLauncher.cpp). Inspect the visible process for the exact packaged executable path; retain actual window and graceful shutdown requirements.
- Hosted Linux rerun 38386061709 fixes media tests and leaves one adaptive normal-transfer timeout. Logs show bench and CLI JVMs still overlapping: Gradle configuration cache ignores --no-parallel (official Gradle configuration_cache docs). Disable configuration cache for full qualification and restrict workers to one to enforce actual isolation. Windows installer and installed startup checks already passed in 38386426914.
- Fully isolated run 38387903810 passes normal adaptive transfers, bit equality and connection-trial acceptance; the sole failure is expected server handler peak 3 vs actual 4. A fully received body can free a client worker while the old server handler is closing. Assert the exposed worker slots and all admission decisions stay <=3, retaining trial acceptance and exclusive byte coverage, rather than equating live handlers to active client connections. No engine behavior change.
